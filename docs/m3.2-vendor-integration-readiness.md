# F3/M4 第一方联调准备与双 AVD 验收说明

## 1. 当前交付状态

本阶段只把第一方 HTTP/read 合同和 C 端边界带入开发联调；它不等于
正式厂商已开通，也不等于真实双 AVD 已验收。当前状态为：

```text
uiScopeStatus             = COMPLETE_69_PAGE_C_END
firstPartyReadStatus      = READY
liveDualAvdAcceptance     = PENDING
runtimeStatus              = VENDOR_BLOCKED
canonicalReviewStatus      = VERIFIED
```

含义如下：

- Flutter 与服务端之间的第一方登录/只读合同、C 端 69 页 UI 和厂商边界已经固定，可以进行 F3 first-party live read 联调。
- 69 页 UI scope 的完成只说明实现和本地视觉/Widget 检查完成；真实
  first-party live 双 AVD 仍是 `PENDING`，不能把两者合并成 PASS。
- 在没有正式适配器、服务端密钥和环境开关时，运行时仍必须明确阻断，不能用 Mock 或旧接口伪造成功。
- 本阶段不调用任何正式厂商接口，也不保存任何正式厂商密钥。

## 2. 移动端安全边界

Flutter 是 OAuth **public client**：

- 只携带公开的 `Client-Id`；
- 不读取 `OAUTH_CLIENT_SECRET`；
- 不发送 `Client-Secret`；
- 不保存短信 AccessKey Secret、RTC App Certificate、腾讯 IM SecretKey、支付私钥或回调密钥；
- Bearer Token、刷新 Token 与设备安装标识只用于第一方服务端认证；
- 开发验证码 Outbox 只允许 `local/development`，预发布和生产配置会直接失败；它只是受控测试 OTP，不是正式 SMS 厂商交付。

CI 会同时扫描 Flutter 源码和最终 APK，发现移动端密钥标记即失败。

## 3. 第一方合同与可读能力

### 3.1 认证合同（非正式 SMS）

- 手机号/短信登录合同和安全会话状态机；
- 设备标识与公开 Client ID；
- development Outbox 安全回读（仅测试 OTP，不代表正式 SMS）；
- 未注册用户资料完善；
- 旋转刷新 Token；
- 启动恢复与过期刷新；
- 服务端登出与本地凭证强制删除。

### 3.2 只读业务

- 当前用户；
- 首页推荐房间；
- 用户和房间搜索；
- 房间权威快照；
- 钱包概览；
- 钻石余额；
- 支付订单/状态查询（只读）；
- 充值商品目录第一方 read（`CM-002`）；
- 服务端厂商接入准备状态。

### 3.3 强制阻断与支付边界

- 房间上麦、开麦、公屏发送、送礼和房间治理写入；
- RTC 加入频道和发布音频；
- 腾讯 IM 登录、收发消息和会话同步；
- 支付订单创建、充值支付和渠道调起；
- Push 投递和对象存储上传。

房间以 `HTTP_SNAPSHOT_ONLY` 模式展示。仅允许查看成员与权威快照；所有写入权限在领域策略层返回 false。

充值目录已有第一方 read，但订单创建/付款仍是 `VENDOR_BLOCKED`；“能读目录”不能推导“能下单”或“支付成功”。

## 4. 六项正式厂商状态

下表是 F3/M4 当前唯一正式厂商状态，六项都必须 fail-closed：

| 正式能力 | `runtimeStatus` | 说明 |
| --- | --- | --- |
| SMS | `VENDOR_BLOCKED` | development Outbox 不是正式短信；无厂商投递/回执。 |
| RTC | `VENDOR_BLOCKED` | 无正式媒体 SDK、Token join、发布或音频成功。 |
| IM | `VENDOR_BLOCKED` | 无腾讯 IM session、实时收发或同步成功。 |
| PAYMENT | `VENDOR_BLOCKED` | 无正式支付下单、SDK 调起、回调或成功。 |
| PUSH | `VENDOR_BLOCKED` | 系统通知权限与 Push 厂商投递严格分离。 |
| OBJECT_STORAGE | `VENDOR_BLOCKED` | 无对象存储凭据、上传或媒体成功。 |

客户端遇到这些状态必须展示明确不可用/恢复提示，不得把本地 Mock、缺失适配器或 development Outbox 写成正式厂商 PASS。

## 5. 服务端厂商状态契约

认证后调用：

```text
GET /app-register-api/vendor/v1/readiness
```

响应包含：

- 契约版本；
- 总体接入边界状态；
- 运行时适配器状态；
- SMS、RTC、IM、PAYMENT、PUSH、OBJECT_STORAGE 各自的服务端端口；
- 缺失配置的**键名**；
- 必须保留在服务端的 Secret 属性名。

响应不包含任何 Secret 值。Flutter “接入”页直接展示该服务端权威状态，不自行推断厂商是否已启用。

## 6. 双 AVD 验收矩阵（当前 PENDING）

矩阵和 runner 是验收方法，不是已通过的证据。当前
`liveDualAvdAcceptance = PENDING`；在两台 AVD 都产出同一候选 SHA 的受保护
证据前，不得写任何 live AVD `PASS`。

| AVD | Android API | Profile | 物理覆盖 | Density | Flutter 逻辑视口 |
|---|---:|---|---:|---:|---:|
| AVD-A | 36 | pixel_7_pro | 1170×2532 | 480 | 390×844 |
| AVD-B | 35 | pixel_2 | 864×1920 | 384 | 360×800 |

每台 AVD 都运行同一条真实 Flutter 启动链路：

1. 隐私同意；
2. 创建短信挑战；
3. 开发 Outbox 回读验证码；
4. Public Client 短信登录；
5. 首页真实只读接口；
6. 搜索用户和房间；
7. 房间 `HTTP_SNAPSHOT_ONLY`；
8. 服务端厂商准备状态；
9. 腾讯 IM `VENDOR_BLOCKED`；
10. 当前用户、钱包、订单与支付发起阻断；
11. 服务端登出和本地会话删除。

集成测试会同时断言：

- `MediaQuery` 逻辑尺寸与指定视口完全一致；
- DPR 与 AVD 配置一致；
- 所有必需第一方接口均被调用；
- 请求中没有 Client Secret 或厂商 Secret；
- 合同服务器没有调用任何生产 Provider；
- 截图、Flutter Drive 日志、Logcat、请求 JSONL、APK SHA-256、页面覆盖 CSV 和测试用例 CSV 均存在。

## 7. 验收工件

每台 AVD 上传独立 evidence artifact：

```text

contract-server/summary.json
```

Aggregate Job 下载两套证据，生成：

```text
aggregate-verdict.txt
aggregate-verdict.json
page_coverage.csv
test_cases.csv

```

任意一台 AVD、任意必需接口、视口、截图、密钥扫描或 fail-closed 断言失败，Aggregate 必须失败。

## 8. 下一阶段允许开始的工作

在 F3 first-party reads 稳定且 M4 双 AVD Aggregate 全绿后，才可以按下列顺序申请正式厂商接入：

1. 在服务端实现短信 `SmsDeliveryPort`，先接厂商沙箱与回执；
2. 在服务端实现 RTC Token 端口，在 Flutter 实现 RTC SDK 适配器；
3. 在服务端签发腾讯 IM UserSig，在 Flutter 实现实时网关；
4. 在服务端实现支付下单、回调验签、幂等、账本和对账，再开放 Flutter 渠道调起；
5. 依次补齐 PUSH 与 OBJECT_STORAGE 的服务端端口和客户端适配器；
6. 每项能力通过沙箱、故障演练、Secret 扫描和灰度开关后，才允许把对应 `runtimeStatus` 从 `VENDOR_BLOCKED` 变为 `READY`。

不得因为“边界就绪”而直接开启生产流量。
