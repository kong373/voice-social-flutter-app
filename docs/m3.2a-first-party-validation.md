## First-party behavior in scope

- OAuth public-client session contracts and rotating sessions;
- current-user, discovery, search, room snapshot, wallet, order, community,
  and notification reads where the first-party backend exposes them;
- first-party recharge catalog read (`CM-002`);
- explicit fail-closed UI for unavailable writes and provider boundaries;
- no provider secret in the distributed mobile application.

Recharge order creation and payment-channel invocation remain blocked even when
the recharge catalog read succeeds. Reading an order/status is not order
creation or payment.

## Scope exclusions

Commercial membership/VIP and gift-backpack/inventory routes are permanently
`RETIRED` / `OUT_OF_SCOPE`. Guild membership, applications, and member
governance remain in scope under `SC-001`/`SC-002`.

The branch is ready for F3 first-party live integration. It is not accepted as
M4 until Flutter CI, the live development backend contract, and both exact-
viewport Android emulator runs pass on the same candidate SHA.
