# M2.2 — 账号、社交与商业化业务核心（无第三方 SDK）

## 目标

在声网、腾讯 IM、微信支付、支付宝与 Apple IAP 尚未完成申请时，继续实现可以独立开发、自动测试和后端联调的平台业务代码。第三方能力继续通过端口隔离；缺少正式协议或凭据时必须失败关闭，不伪造成功。

## 明确不接入

- Agora、Zego 或其他 RTC SDK
- 腾讯 IM 或其他私聊 SDK
- 微信支付、支付宝、Apple IAP
- 对象存储图片上传
- 原生系统权限和设备会话驱动

页面可以展示这些能力的业务前置条件，但没有正式适配器时不显示虚假的成功状态。

## 关键业务规则

1. 青少年模式只阻止创建新的充值订单；进房、消息、社交、钱包查询、订单查询、退款与其他非充值能力不被禁用。
2. 充值目录可以使用第一方 read；支付结果必须以服务端订单状态为准。未接入正式支付 SDK 时，客户端只读取商品/已有订单，不创建充值订单、不调起支付。
3. 当前后端退款能力是账户级历史退款流程，不把它包装成逐订单退款。
4. 礼物币余额、现金收益、冻结金额和可提现余额必须分开显示。
5. 钱包流水过滤红包、盲盒、魔法球、团子、情书、KTV 等已退役业务子类型。
6. 提现必须经过实名认证、银行卡、最低金额、手续费、余额和重复提交校验。
7. 好友请求和工单进度只有在后端协议明确存在时开放；否则展示不可用原因，不自行模拟线上处理。
8. 实名认证采用第一方人工审核契约：Live 可向第一方后端提交 `legalName` 与 `identityNumber`，响应必须是 `FIRST_PARTY_MANUAL_REVIEW` 且 `providerInvocation=false`；后端只持久化脱敏结果，不代表正式第三方实名厂商接入。
9. OS 权限和设备会话撤销需要原生适配器或后端接口；未具备时只能查看已知状态并引导系统设置。
10. 举报和反馈提交保留真实文字证据；图片凭证在对象存储接入前不伪造上传。
