## 2. 结论词与边界

最终结果只能使用 ANDROID_EMULATOR_PASS、ANDROID_EMULATOR_FAIL 或 BLOCKED。执行前和证据尚未回收时使用 PENDING_CLOUD_RUN 作为内部执行状态，不得把它改写成 PASS。

必须始终单列：

- REAL_DEVICE_PENDING：尚未使用 Android 实体设备验证。
- IOS_PENDING：尚未使用 iOS Simulator 或 iPhone 验证。
- VENDOR_BLOCKED：RTC、腾讯 IM、微信支付、支付宝、Apple IAP、推送、对象存储和部分原生权限适配器尚未接入。
- MISSING_IMPLEMENTATION：Manifest 中有 Page ID，但没有真实页面或可执行逻辑。
- NOT_APPLICABLE：确实不适用，并必须写明理由。

Mock 业务成功只能描述为 Mock/离线业务通过，不能描述为真实语音、真实 IM、真实支付、真实推送或真实后端联调通过。

## 4. 构建与 APK 基线

### 4.1 参考 APK 黑盒轮次

1. 使用已核验哈希的参考 APK，不修改包内容。
2. 由 apkanalyzer 或 aapt 自动读取 package name、minSdk、targetSdk、versionName、versionCode 和 ABI；不得猜测。
3. 清空 Logcat，记录旧安装版本。
4. 先 adb install -r；签名冲突时记录证据，再卸载旧包并重新安装。
5. 验证能安装、能启动、非白屏、无立即 Crash/ANR、断网不无限 loading。
6. 这一轮只形成 APK 黑盒基线，不等于 69 页覆盖。

### 4.2 QA Debug APK

云 CI 使用实际 commit 构建：

~~~bash
flutter build apk --debug \
  --dart-define=BACKEND_MODE=mock \
  --dart-define=ENABLE_QA_CONSOLE=true \
  --dart-define=GIT_COMMIT=<tested-sha> \
  --dart-define=PACKAGE_VERSION=0.5.0+5
~~~

产物命名为 voice-social-app-m2.4-qa-debug.apk，计算新 SHA-256 并写入 apk_sha256.txt。不得用 QA APK 的结果冒充参考 APK 黑盒结果。

## 5. AVD 双环境矩阵

两个 AVD 顺序运行、冷启动、禁用旧快照，均为 Portrait。具体 API 必须从 APK manifest 和云 SDK 可用性计算后写入 avd_matrix.csv。

| 环境 | 用途 | API | ABI/硬件 | 必测内容 |
| --- | --- | --- | --- | --- |
| AVD-A | 主验收 | targetSdk 对应或不低于 targetSdk 的稳定 Google APIs 镜像 | Linux Runner 架构匹配；常见 Pixel | 69 页、15 条流程、离线、日志、性能、截图和录屏 |
| AVD-B | 兼容性 | minSdk 对应或最接近且不低于 minSdk 的可用镜像 | 架构匹配；较小屏设备 | 关键登录、进房、礼物、支付边界、消息、公会和已修复 P1 回归 |

每个 AVD 记录名称、API、Android 版本、ABI、型号、物理分辨率、density、实际 MediaQuery.size、devicePixelRatio、font scale、语言、时区和剩余存储。Emulator 的系统栏会改变可用高度，不得用 wm size 冒充逻辑视口。

## 6. 执行阶段

### Phase 0：静态和单元门禁

1. dart format --output=none --set-exit-if-changed lib test integration_test test_driver
2. flutter analyze
3. flutter test --coverage --concurrency=1 --timeout=60s
4. 验证 Manifest 为精确 69 ID、无重复、无非法新增，QA catalog 与 Manifest 一一对应。
5. 验证 Release/非开关 Debug 中 QA 控制台不可见、不可路由。

### Phase 1：参考 APK 黑盒

按第 4.1 节完成安装、启动、离线冷启动和初始 Logcat 检查。结果保持独立记录。

### Phase 2：QA APK 与 69 页目录

从 QA 控制台验证：

- 69 Page ID 目录、搜索和 AC/DS/US/RM/MS/CM/SC 筛选；
- 真实 Widget/Class、源码路径和普通用户入口；
- 直接打开真实页面；
- 16 种角色、16 种页面状态、Mock 场景、网络场景和数据重置；
- BackendMode、Git commit、package version、MediaQuery、DPR、font scale；
- 一键返回 QA 目录。

QA 直接入口不能替代普通用户入口测试；发现通用占位页时必须记 MISSING_IMPLEMENTATION 或路由 FAIL。

### Phase 3：逐页覆盖

以 docs/qa/m2.4-page-coverage.md 和 page_coverage.csv 为执行清单。每个 Page ID 必须记录：真实类和源码、普通入口、QA 入口、角色、前置条件、必要状态、AVD-A/B、全部按钮、两个精确视口、1.3×、键盘、滚动、截图、视频、日志、结果、缺陷和备注。

### Phase 5：离线

在 AVD 中启用飞行模式并用 ping 证明真实断网。断网后执行冷启动、协议、Mock 登录、四根导航、搜索、进离房、上下麦、公屏、礼物、动态、关系、钱包、Mock 充值、订单、消息、通知、公会、CP、任务、PK 和杀进程重启。

离线标准：无无限 loading；普通点击 500 ms 内有视觉反馈；Mock 操作 3 秒内完成或明确报错；无 Crash/ANR；不连接生产或供应商接口；不把 Mock 成功描述为真实成功。测试后恢复网络并验证。

## 7. 角色与状态矩阵

角色至少包括：游客、注册用户、普通听众、麦上用户、房管、房主、平台管理角色、公会成员、公会管理员、公会会长、青少年模式用户、被禁言用户、被封禁用户、实名未认证、实名认证中、实名已通过。

状态集合：normal、loading、empty、error、offline、permission、permissionDenied、disabled、conflict、submitting、success、expired、unavailable、reconnecting、closed、restricted。

不得机械地让每页覆盖全部状态；state_matrix.csv 必须列出页面真正需要的状态及 NOT_APPLICABLE 理由。角色权限必须验证精确目标，尤其是房管操作、入会审核、拉黑、举报、退款、注销、关闭房间和认输。

## 8. 精确视口、文字、键盘、滚动与无障碍

Widget/visual 测试覆盖全部 69 ID：

- Android 360×800，fontScale 1.0；
- Android 360×800，fontScale 1.3；
- Android 390×844，fontScale 1.0；
- Android 390×844，fontScale 1.3。

Emulator 另测系统栏、系统返回键、软键盘、生命周期和真实滚动。要求：

- 标题、正文、按钮无遮挡或 RenderFlex overflow；
- 输入框和主按钮在键盘弹出后仍可达，失败后输入保留；
- 长列表保留顶部、中段和底部证据；
- 点击区域不小于 44×44 逻辑像素；
- 状态不只靠颜色区分；错误文字可读并有恢复动作。

每个真实页面至少保留 1 张 1.0× normal 和 1 张 1.3× normal 截图，最低 138 张。文件名为 {PageID}-{state}-{AVD}-{viewport}-{fontScale}.png。

## 9. 安全、产品硬约束与供应商边界

必须验证：

- 根导航固定为首页/发现/消息/我的；DS-001 是首页，DS-004 是发现动态流。
- 有效房间入口直接进入 RM-004；RM-003 只处理校验和失效恢复。
- RM-004 固定 8 麦，无第 9 个房主麦；麦位状态完整。
- 公屏不伪造进房前或断线期间历史；重连显示指定历史限制提示。
- 房内礼物保持 Bottom Sheet 和房间上下文；离房真实退出；房主离开与关闭分离。
- Android 支付只显示微信支付和支付宝；支付结果以服务端状态为准。
- 青少年模式只阻止创建新充值订单。
- 高风险操作均二次确认。
- 可见 UI、有效路由、推荐位、Mock 数据、礼物和活动目录不得出现红包、red packet、KTV、点歌、演唱、合唱、盲盒、blind box、魔法球、magic ball、团子、dango、情书、love letter、随机遇见、随机匹配、附近的人、附近房间、扫码、易票联。

内部 deny-list、后端过滤器和测试断言中的关键词可作为审计实现存在，但必须证明不会渲染到可见 UI。否定式宣传文案也不豁免“可见命中为 0”的标准。

供应商能力只能验证诚实边界和 fail closed：RTC、腾讯 IM、微信支付、支付宝、Apple IAP、推送、对象存储和原生权限不得伪造成功。

## 10. 日志、稳定性和性能

全程保存 threadtime Logcat，并扫描：FATAL EXCEPTION、ANR、RenderFlex overflow、setState() called after dispose、deactivated widget、Unhandled Exception、Null check、Bad state、LateInitializationError、PlatformException、MissingPluginException、SocketException、TimeoutException。

模拟器门槛：

- Crash、ANR、持续白屏为 0；
- 普通点击 500 ms 内反馈，Mock 操作 3 秒内完成；
- 冷启动建议不超过 5 秒，热启动不超过 2.5 秒；超出记 P2 并注明宿主；
- 连续 10 次进退房后 GC 并等待稳定，PSS 相对初始稳定值增长超过 40%需调查；
- 30 分钟离线操作无崩溃；
- 1000 次限定包名 Monkey 无 Crash/ANR。

模拟器性能只作为同一 Runner/AVD 的回归基准，不得写成真实设备性能。

## 12. 缺陷处理

先保存复现证据，再分配 M24-EMU-NNN。修复后必须增加自动化回归，执行定向测试、全量 flutter test、重建 QA APK，并在 AVD-A 复测；P1 和关键 P2 同时在 AVD-B 复测。不得删除失败测试、降低断言、扩大视口、无限增加超时或屏蔽异常。

## 13. 最终通过门槛

只有同时满足以下条件，报告才能写 ANDROID_EMULATOR_PASS：

1. 参考 APK 哈希一致，或 QA APK 有明确受测 commit、构建信息和新 SHA。
2. flutter analyze、全部 flutter test、AVD-A integration_test 通过，关键流程在 AVD-B 通过。
3. 69 Page ID 全部映射且 MISSING_IMPLEMENTATION=0。
4. FLOW-001～FLOW-015 全部完成并有证据。
5. 所有不依赖供应商的页面和按钮通过；供应商边界诚实且 fail closed。
6. 无 P0、无未解决 P1；P2 已修复或有书面接受。
7. 无 Crash、ANR、RenderFlex overflow；大字、键盘、滚动、8 麦、房内礼物、离房、Android 支付渠道、青少年规则和公屏历史规则通过。
8. 禁止功能可见命中为 0，离线主流程通过。
9. 报告仍单列 REAL_DEVICE_PENDING、IOS_PENDING、VENDOR_BLOCKED。

在云 CI 和 Emulator 证据回收前，本轮结论保持 PENDING_CLOUD_RUN。
