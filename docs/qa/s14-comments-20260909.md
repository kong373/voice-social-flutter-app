## 实现边界

- BackendRouteCatalog 仅追加 `dynamicCommentDelete`，默认 POST `/app-mini-api/mini/v1/dynamic/comment/delete`。正文仅 `{dynamicId,commentId}`，显式 X-Request-Id。严格校验返回目标、DELETED/deleted、两个 false 能力及非负整数 commentCount。
- DynamicComment 保存状态、服务端 canDelete/canReply、父状态/占位；缺能力默认 false，不推断 App role。状态/正文/占位矛盾拒绝，列表只接受 PUBLISHED；历史创建回放允许空正文 DELETED/HIDDEN，不展示归档正文。父删除保留已发布子回复。
- 删除显式弹窗确认；动作由服务端能力控制。确认后只刷新服务端 post/count 和 comments，不本地减计数或删除子回复。回复沿原 parentCommentId，不扩展动态本体权限。
- CommentActions 是评论专用能力接口，既有 DynamicRepository 调用者无需添加伪实现。Backend 与 Mock 共用 repository 生命周期的 CommentMutationJournal：每账号一个未决评论操作，按账号/身份代际分离 Future；未决时不换目标/内容。记录原 key 与只读 body，重复点击合并请求，旧 key 不得绑定新目标。未知后保守保留原操作，不因后来普通拒绝自动产生新 key。
- 新 deleteComment 与原 addComment 均复用已有 `postBoundToIdentity`；发送、401 恢复和响应交付绑定身份。AppDependencies 仅给 BackendDynamicRepository 接现有 identityGeneration/Listenable。
- 页面销毁不销毁 repository 未决记录；换账号清可见评论、输入、回复选择和确认弹窗，旧代际不得更新新账号页面。返回原账号/重建页面恢复原请求。仅内存恢复，不宣称进程退出/应用重启后可恢复，不新增磁盘存储。
- Mock 按当前模拟用户与真实模拟 post/comment 作者判断权限，第三人拒绝，软删除保留父关联；不能作为 live 成功回执。
