# 反馈工单回复

US-010 从本人反馈详情展示服务端 `events` 的提交、客服回复、用户补充及处理记录，文字只按普通文本显示，时间沿用本地时间格式。历史列表仍支持没有 events 的摘要；实际详情若 events 字段畸形，不以空记录掩盖协议错误。

补充接口：`POST /app-mini-api/mini/v1/support/tickets/{ticketId}/replies`，Bearer 会话与 `X-Request-Id`，body 仅 `message`（去除首尾空白后1–1000字符）。不接受用户ID、状态或管理身份。凭据留在现有认证层，不入日志/制品。

前端合并同一未完成提交；不确定结果保留同一请求标识，明确失败后允许修正内容。成功必须收到同一工单、有效版本和对应USER MESSAGE记录；不根据点击/HTTP空响应伪造记录。请求前和结果返回时核对当前账号，切换账号的旧结果拒收。

详情初次刷新成功前不开放回复。SUBMITTED/ACCEPTED/PROCESSING/WAITING_USER允许补充；RESOLVED/CLOSED/未知状态不开放。提交中禁止刷新和二次提交，失败保留草稿，成功清空。409重新获取权威详情，可能隐藏已关闭工单的输入，不自动重发。关闭与解决分开显示。

管理端权限、工单状态迁移、幂等收据和审计均由Backend控制；本次无CPS佣金、礼物分账或第三方调用变更。单元/Widget/协议测试不能替代普通App与实际Admin端同候选处理链路验收。
