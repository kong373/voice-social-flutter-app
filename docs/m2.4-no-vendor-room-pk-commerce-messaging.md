# M2.4 — Room PK, commerce catalog, and messaging business core

## Goal

Complete the remaining business that can be built before RTC, Tencent IM, payment-provider SDKs, object storage, and native permission adapters are approved.

## Room PK

- RM-013 supports room search, hot-room suggestions, exact opponent selection, punishment text validation, 5/10/15-minute durations, outgoing invitation state, incoming accept/reject, and recent records.
- RM-014 supports server-authoritative battle polling, remaining time, both-room scores, supporter lists, result settlement, and a high-risk surrender confirmation where the backend supports it.
- Only room owners receive the PK entry.
- Returning from the PK page does not leave the room or end the battle.
- Leaving an active-PK room displays an explicit risk warning.
- Random matching, skills, taunts, instant-kill mechanics, and mini-games are deliberately excluded.

Confirmed HTTP routes:

- `/app-api/activityPk/inviteRoomPk`
- `/app-api/activityPk/acceptRoomPkInvitation`
- `/app-api/activityPk/rejectRoomPkInvitation`
- `/app-api/activityPk/getRoomPkProgress`
- `/app-api/activityPk/getRoomFightRecord`
- `/app-api/activityPk/getRoomPkHotRoomList`
- `/app-api/activityPk/searchRoomPk`

Incoming invitation delivery still depends on the room real-time transport. Live mode therefore does not fabricate an inbox before that transport is connected.

## Recharge, gifts, membership, decorations, and backpack

- CM-002 displays the account, gift-coin balance, authoritative product catalog, selected tier, youth-mode restriction, and the distinction between gift coins and creator cash income.
- CM-003 displays the selected product, account, amount, and platform-specific channels. Android allows only WeChat Pay and Alipay. iOS allows only Apple IAP.
- CM-004 refreshes the server order state and never treats a provider return as final success.
- CM-009 exposes only ordinary gifts and backpack assets. Room sending remains a bottom sheet over RM-004 and keeps the room, target, gift, and quantity context when the user opens recharge.
- CM-010 provides membership status, gift-coin membership purchase, owned decorations, exact equip/unequip state, and backpack assets.
- Live recharge catalog fails closed because the current backend does not expose an authoritative fixed-product catalog.
- Payment SDK invocation remains unavailable until provider applications are complete.

## Messaging and notifications

- MS-001 provides a repository-backed conversation list, unread counts, exact-conversation routing, notification entry, and recovery entry.
- MS-002 supports scoped private-history rendering and mock send-state testing. Live send stays disabled until Tencent IM is connected.
- MS-003 provides separate system and interaction notification lists and server-backed interaction clearing.
- MS-004 marks a notification read and routes valid targets to users, rooms, dynamics, or orders.
- MS-005 preserves the notification context when a target is deleted, closed, expired, or otherwise unavailable.
- MS-006 exposes private-realtime availability, native notification permission, last server notification sync, and honest recovery boundaries.
- No private message, history page, unread count, or notification-permission success is fabricated in Live mode.

Confirmed HTTP boundaries include:

- `/app-api/user/imMessage/queryChat`
- `/app-api/user/imMessage/queryUserStatus`
- `/app-api/user/imMessage/getUserInfoInChat`
- `/app-api/dynamic/queryUserDynamicNotify`
- `/app-api/dynamic/emptyUserDynamicNotify`
- `/app-api/dynamic/queryDynamicNotifyRedHot`
- `/app-api/nolg/getPushMsg`
- `/app-mini-api/mini/v1/message/permission/{targetUserId}`

## Permanent exclusions

The new business layers do not expose red packets, KTV/song/singing/chorus, blind boxes, magic ball, dango, love letters, random matching, nearby people, scanning, or unconfirmed game entries.
